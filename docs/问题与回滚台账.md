# 问题与回滚台账

> 这份文件只干两件事：**记录出过什么问题**、**随时能退回某个状态**。
> 每修完一个坑，必须在下面「问题记录」里加一条；每个发布节点打一个 tag（见「基线」）。
> 谁发现问题谁补一条，不需要写得漂亮，写清楚「什么时候、什么现象、怎么修的、怎么退回去」就够。

---

## 1. 回滚三板斧（照着敲就行）

先 `cd` 到仓库根目录，`git fetch origin` 拉一下最新。

### ① 整体退回某个基线（最常用）

```bash
git checkout main
git reset --hard <基线 tag 或提交号>
git push --force-with-lease origin main      # 需要 owner 权限（组员做不到，找 P1）
```

### ② 只撤销某一次提交（保留后面的改动）

```bash
git switch -c fix/rollback-<说明>
git revert <提交号>          # 生成一个「反向提交」，历史不丢
git push -u origin fix/rollback-<说明>        # 然后在 GitHub 开 PR 合并
```

### ③ 只要某个文件退回旧版本

```bash
git checkout <基线 tag> -- 路径/文件.ts
git commit -m "revert: 把 xxx 退回 <tag> 版本"
```

> 铁律：**永远不用 `git reset` 动别人正在用的分支**。组员分支用 ②（revert）。

## 4. 下次怎么补一条

1. 现象写**自己能复现的**（「点登录 → 白屏 → 控制台 `JSON.parse` 报错」）；
2. 根因写**一句话**，能指到文件最好；
3. 修复写提交号 / PR 号；
4. 回滚写**具体命令或提交号**——写「回滚一下」等于没写；
5. 如果暴露了流程漏洞，去 `docs/必读1-开发约定.md` 补一条规矩，并在「修复」里注明「已加规矩」。
